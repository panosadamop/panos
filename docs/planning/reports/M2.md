## Exit criterion

> *Forbidden and approval-required actions cannot bypass policy.*

✅ **Met.** `tests/security/` runs every consequential action through alternative routes and asserts the runtime demands approval or denies, **and that no process is spawned**. The routes are:
- a direct shell;
- nested interpreters (`bash -c`, `cmd /c`, `wsl`, `powershell -Command`, `-EncodedCommand`);
- wrappers (`env`, `timeout`);
- Git config/alias injection and `--git-dir`;
- dynamic commands;
- approval tokens reused for a different command or file.

Forged, replayed, expired and action-changed approvals are all rejected and audited.

## Incidents and deviations

1. **⚠ Microsoft Defender detections on this machine (14:36 local time).** Two of my *test* command lines contained attack-shaped strings (a download-and-execute pattern and an HTTP-POST file upload, used only as parser input), and the PowerShell parser was then invoked with `-EncodedCommand`. Defender flagged them as threat **2147948670** and blocked those processes. **Nothing malicious ran.** On a managed Netcompany laptop these alerts may have reached IT security, so you may want to give them a heads-up.
   - Remediation: the parser no longer uses `-EncodedCommand` (stdin + `-Command -`).
   - Attack-shaped strings are kept off command lines; test inputs use benign equivalents inside test files.
   - Recorded in ADR-007 and `considerations.md`.
2. **New action classes beyond PERMISSIONS.md** for shell classification: `shell.*`, `net.fetch`, `net.upload`, `git.mutate.local`, `git.destructive`. Levels follow the spec's intent: `net.upload` is P3, not P4, because PERMISSIONS only fixes browser uploads at P4.
3. **Policy overrides are passed in `ToolContext`.** There is no persisted per-project policy entity yet; it arrives with the project registry in M3.

## Known limitations

- **Accepted residual risk (ADR-007):** allowlisted build/test commands (`npm test`, `pytest`…) execute repository code. Mitigations: project scoping, checkpoints (M5), and approval for anything unrecognised.
- **Job Object assignment race:** a grandchild spawned in the first microseconds may escape the job; the psutil fallback handles it.
- `fs.delete`/`fs.move` resolve the final symlink, so they act on the link target (inside the project), not on the link itself.
- Delete "recoverability" uses Git only. Checkpoints (M5) will widen what counts as recoverable.
- Classification is conservative. Some legitimate compound commands (e.g. `make test` without a project allowlist, `bash script.sh`) will ask for approval.
- The PowerShell parser needs Windows PowerShell or pwsh; without one, PowerShell scripts classify as `shell.unknown` (fail closed).
- Coverage under-reports `app.py`/`container.py` lifespan code (it runs in TestClient's portal thread) and `server.py` (run in the e2e subprocess).
- POSIX-specific code (`posix/process.py`, `0600` files) is untested locally; there is still no CI remote.
