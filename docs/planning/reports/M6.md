## What you can do now

```text
panos new -n shop "an online shop…"         → targeted questions (persisted, resumable)
panos interview answer itv_… q1 "…" | --skip → answers become provenance; skips become assumptions
panos interview complete itv_…              → draft BR/FR/EPIC/FEAT/US/AC/TC/NFR/RULE/API/DATA/RISK… + stack ADR
panos req list|show|add|edit|approve|reject|link|trace|clear-stale -p shop
panos project estimate shop                 → points, hours, person-days, cost by role, sprint plan
panos project scaffold shop --open          → skeleton + docs/requirements/*.md + openapi.yaml + .claude/skills, opens the IDE
panos project docs|skills shop              → regenerate documents / skills
```

## Known limitations

1. **Live model quality:** the pipeline works with qwen2.5-coder:7b, but its specifications are thin; all automated tests use scripted agents.
2. **Only Markdown and OpenAPI artifacts are generated.** DOCX/XLSX/PPTX/PDF export (FR-029, BR-028) is open.
3. **No cloud scaffolding:** cloud providers (GCP/Azure/AWS) have no scaffold templates, and official generators (Spring Initializr etc.) are not used.
4. **Requirement endpoints are project-scoped** (keys are per project), not API.md's global `/requirements/{id}`.
5. **No `implements` evidence from coding jobs yet:** they don't record links automatically, so the evidence links in the traceability view are manual for now.
6. **The interview is one round:** a single set of questions, no follow-up questions based on the answers.
