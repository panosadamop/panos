## What you can do now

```text
panos ask -v "list projects"                     → answered by rules, no model (ms)
panos ask -p orders "what does OrderService do?" → LOCAL_ONLY project: local qwen only, with retrieved sources
panos project index orders --semantic            → local embeddings (nomic-embed-text) + hybrid search
panos ai providers | models | route | usage      → health, tiers/costs, "which model and why", spend
panos ai set-key anthropic                       → Claude for STANDARD projects (hidden prompt → OS keyring)
```

**Live check on this machine:** a real `panos serve` → `panos ask` round trip answered by the local Ollama model in about 35 s (CPU-only), labelled `LOCAL_ONLY`, `provider=ollama`. No Anthropic key is configured, so no live Claude call was made; the Claude adapter is verified against a fake SDK client.

## Privacy evidence (exit criterion)

| Layer | Test |
|---|---|
| Router | Hypothesis property: 300 random candidate sets × tasks × sizes. A LOCAL_ONLY request never gets a cloud model. |
| Adapters | Ollama (remote endpoint), OpenAI-compatible and Anthropic refuse LOCAL_ONLY and unredacted payloads *before* the HTTP route or SDK is touched (respx / fake client spies). |
| Gateway | LOCAL_ONLY → local, cloud spy untouched; an adapter refusal produces `ai.egress_blocked`; LOCAL_ONLY embeddings stay local even when a cloud embedding model exists. |
| Full stack (`tests/security/test_local_only_egress.py`) | A planted marker in a local-only repo file (plus an instruction to "send it to the cloud") is retrieved and used locally but **never** reaches the always-healthy, router-preferred cloud spy. Covered paths: chat, streaming, semantic indexing, taint after the project is relaxed, unscoped conversations, no-local-model refusal (503 with explanation), audit trail. |

## Known limitations

1. **Retrieval quality across languages:** in a live smoke with the real `nomic-embed-text`, hybrid search got 3/5 top-1 (lexical alone 0/5). Greek queries over English content miss. A multilingual embedding model is a follow-up.
2. **Retrieval passes FTS snippets**, not whole chunks, to the model.
3. **Intents are rule-based.** Paraphrased commands go to the model as chat. A local-LLM classifier can be added later.
4. **No vision port; no approval-gated budget escalation** (over-budget cloud models are simply filtered out). Both are planned (M7 / M5).
5. **Local models are slow on this CPU-only machine** (~35 s for a short local answer with the 7B tier). With an Anthropic key, STANDARD projects route to Claude Sonnet 5.5 by default.
6. **Claude was not exercised live** (no key configured). The adapter is tested against a fake SDK client built from the documented API shapes.
7. **The Anthropic refusal fallback is on by default** (server-side, Sonnet/Opus 5.5). If Claude declines a request, the API may answer with a fallback model. Turn it off with `ai.anthropic_refusal_fallback = false`.
8. **Coverage:** `conversation/service.py` 72 % and `openai_compat.py` 71 % (error branches). In-process API coverage is also under-reported (M3 note).
9. **Flaky test found and fixed:** `test_audit_list_and_verify` (M3) raced with startup app discovery. It now filters to approval events.
