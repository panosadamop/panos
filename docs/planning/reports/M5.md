## What you can do now

```text
panos job start -p repo "add input validation to signup"  → background coding job
panos job watch job_…            → follows it; stops when it finishes or needs you
panos approvals approve apr_…    → the commit runs only for the exact approved tree
panos job rollback job_…         → restore the checkpoint (your .git is not touched)
panos job pause | resume | cancel job_…
panos job start -p repo --cmd python --cmd manage.py --cmd test "run tests"
panos ask -p repo "implement …"  → a work request in chat starts a coding job
```

**Conclusion:**
- Orchestration, checkpoints, verification, repair limits, privacy (all local, $0) and the visible failure states behave as designed with a real model.
- qwen2.5-coder:7b is not reliable enough to finish even a trivial feature unattended. Local-only coding on this laptop is assistive at best.
- With a Claude key, STANDARD projects use Sonnet 5.5 for coding.
- Follow-up: a more forgiving edit format for small models (search/replace blocks instead of JSON), and evaluating qwen2.5-coder:14b / an MoE model for local-only work.

## Known limitations

1. **Quality depends on the model.** The workflow is proven with scripted agents. In three live runs, the local 7B model did not finish the task (details above). STANDARD projects use Claude Sonnet 5.5 once a key is set; Claude was not exercised live (no key).
2. **Reviews and traceability are shallow.** Review findings are reported but not auto-fixed, and the trace check only reports requirement IDs carried by the job.
3. **Approvals:** tokens are kept in memory only, so an approval granted right before a node restart has to be requested again (resume does that). The 30-minute approval lifetime may be short for unattended jobs.
4. **Checkpoints:** no retention pruning, no large-file limit, and nested Git repos are not restored.
5. **Commits:**
   - Planning a commit writes Git blob objects (no refs or index change).
   - Hooks run on the real commit; if a hook rewrites files, `tree_matches_approval: false` is reported.
6. **Docker:** the Docker CLI is not installed on this machine, so live inspection was not exercised (static parsing is).
7. **Notifications** reach `/ws/events` and the log only (desktop and voice in M7).
8. **Pause timing:** pause waits for the current step. A long test run or model call finishes first, unless you cancel.
9. **Two test races were found and fixed** (test code only): a wait helper polled the wrong runner, and a process-liveness check raced with process exit.
